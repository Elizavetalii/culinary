# Руководство пользователя: описание страниц Art Culinary CRM

Базовый адрес приложения при запуске на порту 8000: `http://localhost:8000`.

В руководстве страницы сгруппированы по ролям пользователей. В адресах вида `<int:pk>`, `<slug:slug>`, `<uidb64>` и `<token>` вместо параметра используется реальное значение записи: идентификатор клиента, заказа, маршрута, пользователя или ссылка из письма восстановления пароля.

## 1. Общие страницы входа и восстановления доступа

### Рисунок 1 - Главная страница входа

Адрес: `http://localhost:8000/`

Главная страница открывается при переходе по основному адресу web-приложения. Она предназначена для входа пользователя в систему Art Culinary CRM. На экране отображается форма авторизации, в которой сотрудник вводит электронную почту и пароль.

Порядок работы пользователя:

1. В поле «Электронная почта» пользователь вводит адрес, закрепленный за его учетной записью.
2. В поле «Пароль» пользователь вводит пароль от учетной записи.
3. После заполнения полей пользователь нажимает кнопку «Войти».

Если данные введены корректно, система создает сессию и перенаправляет пользователя в рабочий кабинет согласно его роли. Если email или пароль указаны неверно, вход не выполняется, а пользователь остается на странице авторизации и может повторить попытку. Доступ к функциям CRM без авторизации не предоставляется.

### Рисунок 2 - Страница входа в систему

Адрес: `http://localhost:8000/login/`

Страница входа используется для повторной авторизации пользователя, если он вышел из системы или был перенаправлен на форму входа при попытке открыть закрытый раздел. Состав формы аналогичен главной странице входа: пользователь вводит электронную почту и пароль.

В нижней части формы расположена ссылка «Забыли пароль?». Она используется в случае, если пользователь не может вспомнить пароль или учетная запись требует восстановления доступа. После успешной авторизации пользователь попадает не в общий раздел, а в рабочую область, соответствующую его правам: кабинет менеджера, логиста, сборщика, курьера или администратора.

### Рисунок 3 - Выход из учетной записи

Адрес: `http://localhost:8000/logout/`

Страница выхода завершает текущую пользовательскую сессию. Пользователь переходит по этому адресу через кнопку «Выйти» в верхней панели или в интерфейсе личного кабинета.

После выполнения выхода система удаляет данные текущей сессии. При повторном открытии защищенных разделов пользователь будет перенаправлен на страницу входа. Данный механизм рекомендуется использовать после завершения работы, особенно если приложение открыто на рабочем месте с общим доступом.

### Рисунок 4 - Восстановление пароля

Адрес: `http://localhost:8000/password-reset/`

Страница предназначена для восстановления доступа к учетной записи. Пользователь указывает электронную почту, которая используется для входа в систему, и нажимает кнопку «Отправить письмо».

После отправки формы система проверяет наличие учетной записи с указанным адресом. Если учетная запись существует и активна, на почту отправляется ссылка для установки нового пароля. Если пользователь ошибся при вводе email, он может вернуться к форме и отправить запрос повторно. Ссылка «Назад к входу» возвращает пользователя на страницу авторизации.

### Рисунок 5 - Подтверждение отправки письма

Адрес: `http://localhost:8000/password-reset/done/`

Страница открывается после отправки запроса на восстановление пароля. На экране отображается сообщение о том, что письмо отправлено, если учетная запись с указанной почтой существует.

Пользователь должен проверить корпоративную почту и перейти по ссылке из письма. Если письмо не пришло, рекомендуется проверить правильность указанного адреса, папку «Спам» и повторить отправку запроса. Для возврата к авторизации используется ссылка «Вернуться ко входу».

### Рисунок 6 - Установка нового пароля

Адрес: `http://localhost:8000/reset/<uidb64>/<token>/`

Страница открывается по индивидуальной ссылке из письма восстановления пароля. Пользователь вводит новый пароль и повторяет его во втором поле для подтверждения.

Порядок работы:

1. В поле «Новый пароль» вводится новый пароль.
2. В поле «Повторите пароль» пароль вводится повторно.
3. Пользователь нажимает «Сохранить пароль».

Если ссылка действительна, а введенные пароли совпадают и соответствуют требованиям безопасности, система сохраняет новый пароль. Если ссылка устарела или пароль введен некорректно, система выводит ошибку и не изменяет учетные данные.

### Рисунок 7 - Пароль обновлен

Адрес: `http://localhost:8000/reset/done/`

Страница подтверждает успешное изменение пароля. Пользователь видит сообщение о том, что пароль обновлен, и переходит к форме входа по ссылке «Перейти ко входу».

После этого пользователь авторизуется с новым паролем. Старый пароль больше не используется для входа в систему.

### Рисунок 8 - Общий переход в кабинет

Адрес: `http://localhost:8000/dashboard/`

Данный адрес используется системой для определения рабочего раздела пользователя. После входа CRM проверяет роль сотрудника и перенаправляет его в соответствующий кабинет.

Пользователь обычно не работает с этой страницей напрямую. Она выполняет служебную функцию маршрутизации: менеджер попадает в панель менеджера, логист - в панель логиста, сборщик - в панель сборщика, администратор - в панель администратора.

## 2. Страницы роли менеджера

### Рисунок 9 - Панель менеджера

Адрес: `http://localhost:8000/dashboard/manager/`

Панель менеджера является основным экраном для сотрудника, отвечающего за клиентов, заказы, аналитику и отчетность. После входа менеджер видит сводную информацию по рабочим объектам и быстрые переходы к основным разделам.

На странице используются ссылки для перехода к клиентам, заказам, архиву заказов, аналитике, отчетам и проверке доставок. Менеджер начинает работу с этой страницы, чтобы оценить текущую ситуацию и перейти к нужному действию: создать клиента, оформить заказ, проверить отчет или проконтролировать доставку.

### Рисунок 10 - Портал менеджера

Адрес: `http://localhost:8000/manager/`

Портал менеджера представляет упрощенный рабочий экран с быстрым доступом к клиентам и заказам. Он удобен для выполнения базовых операций без перехода в расширенную панель.

Пользователь может выбрать раздел «Клиенты» для работы с клиентской базой или раздел «Заказы» для просмотра и создания заказов. Страница используется как стартовая точка для ежедневной работы менеджера.

### Рисунок 11 - Клиенты в портале менеджера

Адрес: `http://localhost:8000/manager/clients/`

На странице отображается список клиентов в упрощенном виде. Для каждой записи выводятся основные сведения: название клиента, статус, этап сотрудничества и ответственный сотрудник.

Менеджер может применить фильтр, чтобы быстро найти нужного клиента, нажать «Добавить клиента» для создания новой записи или выбрать «Редактировать» у существующего клиента. Если данных нет, система отображает пустой список.

### Рисунок 12 - Создание клиента в портале

Адрес: `http://localhost:8000/manager/clients/create/`

Страница используется для быстрого добавления клиента. Менеджер заполняет форму с данными клиента: название или ФИО, тип клиента, контактную информацию, статус, этап сотрудничества и ответственного сотрудника.

После заполнения формы пользователь нажимает «Сохранить». Если обязательные поля заполнены корректно, система создает карточку клиента и добавляет ее в список. При ошибках заполнения форма остается открытой, а система показывает, какие поля нужно исправить.

### Рисунок 13 - Редактирование клиента в портале

Адрес: `http://localhost:8000/manager/clients/<int:pk>/edit/`

Страница предназначена для изменения сведений о ранее созданном клиенте. Менеджер открывает нужную запись, корректирует контактные данные, статус, этап сотрудничества или ответственного сотрудника и сохраняет изменения.

После сохранения обновленные данные используются во всех связанных разделах: заказах, аналитике, логистике и отчетах. Если пользователь нажимает отмену или покидает страницу без сохранения, изменения не применяются.

### Рисунок 14 - Заказы в портале менеджера

Адрес: `http://localhost:8000/manager/orders/`

На странице отображается список заказов с номером, клиентом, статусом и суммой. Раздел используется для быстрого контроля текущих заказов.

Менеджер может применить фильтр, создать новый заказ или перейти к редактированию существующего. Если заказов нет, система показывает сообщение об отсутствии данных. Страница помогает быстро проверить состояние заказов без открытия расширенного модуля.

### Рисунок 15 - Создание заказа в портале

Адрес: `http://localhost:8000/manager/orders/create/`

Страница используется для оформления нового заказа. Менеджер выбирает клиента, указывает основные параметры заказа, состав, сумму и дополнительные сведения, необходимые для дальнейшей обработки.

После нажатия «Сохранить» система проверяет введенные данные. Если форма заполнена корректно, заказ создается и становится доступен в списке. Далее заказ может использоваться в производстве, логистике и отчетности.

### Рисунок 16 - Редактирование заказа в портале

Адрес: `http://localhost:8000/manager/orders/<int:pk>/edit/`

Страница позволяет изменить параметры существующего заказа. Менеджер может скорректировать клиента, состав заказа, статус, сумму или дату выполнения в зависимости от доступных полей.

После сохранения изменения отражаются в связанных разделах. Например, логист видит актуальные параметры доставки, а аналитика использует обновленные значения заказа.

### Рисунок 17 - Список клиентов

Адрес: `http://localhost:8000/clients/`

Раздел «Клиенты» отображает расширенный список клиентов. В таблице показаны название или ФИО, телефон, электронная почта, этап сотрудничества, статус и дата создания.

Менеджер может:

1. Найти клиента по фильтрам и сортировке.
2. Добавить нового клиента.
3. Открыть карточку клиента.
4. Перейти к редактированию записи.
5. Удалить клиента при наличии прав.

Если список пустой, система предлагает добавить первого клиента или изменить условия фильтрации. Раздел является основным инструментом ведения клиентской базы.

### Рисунок 18 - Создание клиента

Адрес: `http://localhost:8000/clients/create/`

Страница создания клиента содержит расширенную форму. Пользователь вводит основные сведения о клиенте, контактные данные и адрес доставки. Адрес собирается в единую строку, поэтому менеджер может проверить его в блоке предпросмотра.

После заполнения формы нажимается кнопка «Сохранить». Если данные корректны, CRM создает клиента и делает запись доступной в списке. Если обязательные поля не заполнены, система выделяет ошибки и предлагает исправить форму.

### Рисунок 19 - Карточка клиента

Адрес: `http://localhost:8000/clients/<int:pk>/`

Карточка клиента содержит полную информацию о выбранном клиенте. На странице отображаются тип, статус, этап сотрудничества, ответственный менеджер, телефон, email и адрес доставки.

Доступные действия:

1. Нажать «Редактировать» для изменения сведений.
2. Нажать «К списку» для возврата к списку клиентов.
3. Открыть адрес доставки в Google Maps.
4. Обновить этап сотрудничества.
5. Добавить запись во взаимодействия.
6. Просмотреть заказы клиента и историю этапов.

Карточка используется как центральная точка работы с клиентом: здесь менеджер видит текущее состояние отношений и историю действий.

### Рисунок 20 - Редактирование клиента

Адрес: `http://localhost:8000/clients/<int:pk>/edit/`

Страница редактирования открывается из карточки или списка клиентов. Пользователь изменяет данные клиента, адрес доставки и другие параметры.

После нажатия «Сохранить» система обновляет запись. При нажатии «Отмена» пользователь возвращается к предыдущему разделу без применения изменений. Редактирование используется при смене контактов, адреса, статуса или этапа сотрудничества.

### Рисунок 21 - Удаление клиента

Адрес: `http://localhost:8000/clients/<int:pk>/delete/`

Страница подтверждает удаление клиента. Перед выполнением операции система показывает название удаляемой записи и предупреждает, что действие нельзя отменить.

Пользователь выбирает одно из действий: «Удалить» для подтверждения или «Отмена» для возврата без удаления. Удаление следует выполнять только в том случае, если клиентская запись действительно больше не требуется.

### Рисунок 22 - Список заказов

Адрес: `http://localhost:8000/orders/`

Страница заказов отображает таблицу активных заказов. Для каждой записи указаны номер, клиент, статус, сумма и дата доставки.

Менеджер может создавать новые заказы, фильтровать список, открывать архив, выбирать несколько записей, отправлять заказ в архив, редактировать или удалять заказ. Раздел используется для оперативного контроля заказов на всех этапах их обработки.

### Рисунок 23 - Создание заказа

Адрес: `http://localhost:8000/orders/create/`

Форма создания заказа позволяет указать клиента, дату доставки, позиции заказа, количество, цену и комментарии. Система также показывает производственные подсказки: доступность ингредиентов, уже запланированный объем, вес текущего заказа и ограничения клиента.

Пользователь добавляет позиции с помощью кнопки «Добавить позицию». После заполнения всех обязательных данных нажимается «Сохранить». Если система обнаруживает нехватку ингредиентов или превышение лимитов, пользователю отображаются предупреждения, которые нужно учесть перед оформлением заказа.

### Рисунок 24 - Архив заказов

Адрес: `http://localhost:8000/orders/archive/`

Архив содержит заказы, исключенные из активного списка. В таблице отображаются номер, клиент, статус, сумма и дата доставки.

Менеджер может восстановить заказ из архива, если он снова должен отображаться среди активных. Ссылка «К активным» возвращает пользователя к текущим заказам. Архив помогает не удалять завершенные или неактуальные заказы окончательно.

### Рисунок 25 - Массовое удаление заказов

Адрес: `http://localhost:8000/orders/bulk-delete/`

Массовое удаление применяется к заказам, выбранным в списке. Пользователь сначала отмечает необходимые записи, затем запускает операцию удаления выбранных заказов.

Перед использованием функции рекомендуется проверить список выбранных записей, так как операция влияет сразу на несколько заказов. Функция предназначена для очистки ошибочно созданных или неактуальных заказов.

### Рисунок 26 - Обновление статуса заказа

Адрес: `http://localhost:8000/orders/<int:pk>/status/`

Раздел используется для изменения текущего статуса заказа. После выбора нового статуса система сохраняет изменение, и обновленное состояние заказа становится видно в списках менеджера, сборщика и логиста.

Обновление статуса помогает отслеживать движение заказа по процессу: оформление, сборка, готовность, передача в доставку или завершение.

### Рисунок 27 - Перемещение заказа в архив

Адрес: `http://localhost:8000/orders/<int:pk>/archive-toggle/`

Операция переносит заказ в архив или восстанавливает его из архива. Пользователь запускает действие из списка заказов или архива.

После выполнения система меняет состояние записи. Заказ либо исчезает из активного списка и появляется в архиве, либо возвращается обратно в активные заказы.

### Рисунок 28 - Редактирование заказа

Адрес: `http://localhost:8000/orders/<int:pk>/edit/`

На странице редактирования пользователь изменяет данные существующего заказа. Форма содержит сведения о клиенте, дате доставки, позициях заказа, количестве и комментариях.

Система повторно показывает производственные предупреждения, чтобы менеджер видел последствия изменений. После сохранения обновленные данные используются во всех связанных процессах: сборке, доставке и аналитике.

### Рисунок 29 - Удаление заказа

Адрес: `http://localhost:8000/orders/<int:pk>/delete/`

Страница удаления заказа требует подтверждения действия. Пользователь видит номер или описание заказа и предупреждение о невозможности отмены.

Кнопка «Удалить» окончательно удаляет заказ. Ссылка «Отмена» возвращает пользователя без выполнения операции. Удаление рекомендуется использовать только для ошибочных записей.

### Рисунок 30 - Проверка доставок менеджером

Адрес: `http://localhost:8000/logistics/manager/proofs/`

Страница отображает документы доставки, загруженные курьерами. Менеджер видит маршрут, заказ, адрес, статус проверки и файл подтверждения.

Порядок работы:

1. Выбрать статус проверки в фильтре при необходимости.
2. Открыть документ доставки.
3. Проверить корректность файла.
4. Нажать «Подтвердить» или «Отклонить».

После принятия решения статус документа обновляется. Раздел помогает контролировать фактическое выполнение доставок.

### Рисунок 31 - Обновление проверки доставки

Адрес: `http://localhost:8000/logistics/manager/proofs/<int:pk>/`
