# Описание страниц web-приложения Art Culinary CRM

База адресов при запуске на порту 8000: `http://localhost:8000`.

Динамические параметры в адресах, например `<int:pk>`, `<slug:slug>`, `<uidb64>`, `<token>`, заменяются реальными значениями из системы. Страницы сгруппированы по ролям пользователей: сначала перечислены общие страницы доступа, затем разделы менеджера, логиста, курьера, сборщика, администратора и общие коммуникации. В конце отдельно приведены служебные страницы, которые не относятся к одной конкретной роли.

## Общие страницы авторизации и доступа

### Рисунок 1 - Главная страница входа

Адрес: `http://localhost:8000/`

После перехода по адресу приложения пользователь открывает стартовую страницу авторизации Art Culinary CRM. На экране отображается форма входа в систему с полями для ввода электронной почты и пароля. Пользователь вводит учетные данные и нажимает кнопку «Войти». При корректном вводе система создает пользовательскую сессию и перенаправляет сотрудника в рабочий раздел согласно его роли. Если данные указаны неверно, пользователь остается на странице входа и может повторить попытку авторизации.

### Рисунок 2 - Страница входа в систему

Адрес: `http://localhost:8000/login/`

На странице входа пользователь вводит корпоративную электронную почту и пароль. Для отправки данных используется кнопка «Войти». После успешной проверки учетной записи система открывает соответствующий кабинет: менеджера, логиста, сборщика, курьера или администратора. В нижней части формы доступна ссылка «Забыли пароль?», предназначенная для перехода к восстановлению доступа.

### Рисунок 3 - Выход из учетной записи

Адрес: `http://localhost:8000/logout/`

Страница выхода используется для завершения пользовательской сессии. После перехода по адресу система удаляет текущую сессию пользователя и возвращает его к форме авторизации. Данный механизм необходим для безопасного завершения работы в CRM, особенно при использовании общего компьютера.

### Рисунок 4 - Восстановление пароля

Адрес: `http://localhost:8000/password-reset/`

На странице восстановления пароля пользователь указывает электронную почту, привязанную к учетной записи, и нажимает кнопку «Отправить письмо». Система проверяет наличие пользователя с указанным адресом и, если учетная запись существует, отправляет письмо со ссылкой для сброса пароля. На странице также расположена ссылка «Назад к входу», позволяющая вернуться к форме авторизации.

### Рисунок 5 - Подтверждение отправки письма

Адрес: `http://localhost:8000/password-reset/done/`

После отправки формы восстановления система открывает страницу с сообщением «Письмо отправлено». Пользователь получает уведомление о том, что при наличии учетной записи на указанную почту будет отправлена ссылка для сброса пароля. Для возврата к авторизации используется ссылка «Вернуться ко входу».

### Рисунок 6 - Установка нового пароля

Адрес: `http://localhost:8000/reset/<uidb64>/<token>/`

После перехода по ссылке из письма пользователь открывает форму установки нового пароля. На странице отображаются поля «Новый пароль» и «Повторите пароль». После заполнения формы пользователь нажимает кнопку «Сохранить пароль». Если ссылка действительна и пароли совпадают, система сохраняет новый пароль для учетной записи.

### Рисунок 7 - Пароль обновлен

Адрес: `http://localhost:8000/reset/done/`

Страница отображается после успешного изменения пароля. Пользователь видит сообщение о том, что пароль обновлен, и может перейти к форме входа по ссылке «Перейти ко входу». Далее авторизация выполняется уже с новым паролем.

### Рисунок 8 - Общий переход в кабинет

Адрес: `http://localhost:8000/dashboard/`

Данный адрес используется как промежуточный раздел для перенаправления пользователя в кабинет, соответствующий его роли. После авторизации система определяет права сотрудника и открывает нужную панель: менеджера, логиста, сборщика или администратора.

## Страницы роли менеджера

### Рисунок 9 - Панель менеджера

Адрес: `http://localhost:8000/dashboard/manager/`

Панель менеджера является основным рабочим экраном сотрудника, отвечающего за клиентов и заказы. На странице отображаются сводные показатели, быстрые ссылки на клиентов, заказы, аналитику и отчеты. Менеджер использует данный экран для перехода к ежедневным задачам и контроля коммерческой активности.

### Рисунок 10 - Портал менеджера

Адрес: `http://localhost:8000/manager/`

Страница портала менеджера содержит краткую панель с быстрыми переходами к клиентам и заказам. Менеджер видит основные рабочие разделы и может перейти к списку клиентов либо к списку заказов. Экран используется как упрощенная стартовая точка для коммерческой работы.

### Рисунок 11 - Клиенты в портале менеджера

Адрес: `http://localhost:8000/manager/clients/`

На странице отображается список клиентов с основными данными: название, статус, этап сотрудничества и ответственный сотрудник. Пользователь может применить фильтр, добавить нового клиента или перейти к редактированию существующей записи. Раздел помогает менеджеру быстро находить и обновлять клиентскую базу.

### Рисунок 12 - Создание клиента в портале

Адрес: `http://localhost:8000/manager/clients/create/`

Страница содержит форму добавления нового клиента. Менеджер заполняет сведения о клиенте, контактные данные и параметры взаимодействия, после чего нажимает кнопку «Сохранить». После успешного сохранения запись появляется в списке клиентов.

### Рисунок 13 - Редактирование клиента в портале

Адрес: `http://localhost:8000/manager/clients/<int:pk>/edit/`

На странице редактирования менеджер изменяет данные выбранного клиента. Форма используется для обновления контактной информации, статуса, этапа сотрудничества и других параметров. После нажатия кнопки «Сохранить» система записывает изменения и возвращает пользователя к рабочему разделу.

### Рисунок 14 - Заказы в портале менеджера

Адрес: `http://localhost:8000/manager/orders/`

Раздел отображает список заказов с номером, клиентом, статусом и суммой. Менеджер может применить фильтр, создать новый заказ или перейти к редактированию существующего. Страница используется для контроля заказов и их текущего состояния.

### Рисунок 15 - Создание заказа в портале

Адрес: `http://localhost:8000/manager/orders/create/`

На странице создания заказа менеджер заполняет форму с данными клиента, составом заказа, суммой и параметрами выполнения. После нажатия кнопки «Сохранить» система создает новый заказ и делает его доступным в списке заказов.

### Рисунок 16 - Редактирование заказа в портале

Адрес: `http://localhost:8000/manager/orders/<int:pk>/edit/`

Страница предназначена для изменения ранее созданного заказа. Менеджер может скорректировать данные заказа и сохранить изменения. После успешного обновления система использует новые сведения в связанных разделах CRM, включая сборку, логистику и отчетность.

### Рисунок 17 - Список клиентов

Адрес: `http://localhost:8000/clients/`

На странице отображается таблица клиентов с названием или ФИО, телефоном, электронной почтой, этапом, статусом и датой создания. Пользователь может отфильтровать список по статусу и этапу, выбрать сортировку, добавить нового клиента, изменить или удалить существующую запись. Если клиентов нет, система предлагает добавить первого клиента или изменить условия фильтра.

### Рисунок 18 - Создание клиента

Адрес: `http://localhost:8000/clients/create/`

Страница содержит форму создания клиента. Пользователь заполняет основные сведения, контактные данные и адрес доставки. Система формирует предпросмотр полного адреса, чтобы менеджер мог проверить корректность данных перед сохранением. Для завершения используется кнопка «Сохранить».

### Рисунок 19 - Карточка клиента

Адрес: `http://localhost:8000/clients/<int:pk>/`

В карточке клиента отображается основная информация: тип, статус, этап сотрудничества, менеджер, телефон, email и адрес доставки. Пользователь может открыть адрес в Google Maps, обновить этап сотрудничества, просмотреть журнал взаимодействий, заказы клиента и историю этапов. Страница служит центральным разделом для работы с конкретным клиентом.

### Рисунок 20 - Редактирование клиента

Адрес: `http://localhost:8000/clients/<int:pk>/edit/`

На странице редактирования пользователь изменяет сведения о клиенте и адрес доставки. После внесения изменений необходимо нажать кнопку «Сохранить». При отмене действия пользователь возвращается к предыдущему разделу без сохранения новых данных.

### Рисунок 21 - Удаление клиента

Адрес: `http://localhost:8000/clients/<int:pk>/delete/`

Страница подтверждения удаления отображает выбранного клиента и предупреждает, что действие нельзя отменить. Пользователь может подтвердить удаление кнопкой «Удалить» или отказаться от операции по ссылке «Отмена». Такая страница снижает риск случайного удаления важной записи.

### Рисунок 22 - Список заказов

Адрес: `http://localhost:8000/orders/`

На странице заказов отображается таблица с номером, клиентом, статусом, суммой и датой доставки. Менеджер может создать заказ, открыть архив, применить фильтры, выбрать несколько записей, удалить выбранные заказы или перенести заказ в архив. Раздел используется для ежедневного контроля заказов.

### Рисунок 23 - Создание заказа

Адрес: `http://localhost:8000/orders/create/`

Страница содержит форму создания заказа и блок позиций заказа. Пользователь выбирает клиента, дату доставки, добавляет блюда, количество, цену и комментарии. Система показывает производственные подсказки и предупреждения, например о доступности ингредиентов или превышении лимитов. После заполнения формы пользователь нажимает «Сохранить».

### Рисунок 24 - Архив заказов

Адрес: `http://localhost:8000/orders/archive/`

На странице архива отображаются заказы, перенесенные из активного списка. Для каждой записи показываются номер, клиент, статус, сумма и дата доставки. Пользователь может восстановить заказ из архива или вернуться к активным заказам по ссылке «К активным».

### Рисунок 25 - Массовое удаление заказов

Адрес: `http://localhost:8000/orders/bulk-delete/`

Данный адрес используется для обработки операции удаления нескольких выбранных заказов. Пользователь предварительно выбирает записи в списке заказов, после чего система выполняет действие для выбранных элементов. Такая операция применяется при необходимости очистить список от нескольких неактуальных заказов.

### Рисунок 26 - Обновление статуса заказа

Адрес: `http://localhost:8000/orders/<int:pk>/status/`

Страница или обработчик используется для изменения статуса выбранного заказа. После отправки нового значения система обновляет состояние заказа, что влияет на отображение записи в списках менеджера, сборщика и логиста.

### Рисунок 27 - Перемещение заказа в архив

Адрес: `http://localhost:8000/orders/<int:pk>/archive-toggle/`

Данный адрес используется для переноса заказа в архив или восстановления его из архива. После выполнения действия система меняет признак архивности заказа. Пользователь видит обновленное состояние в активном списке или архиве заказов.

### Рисунок 28 - Редактирование заказа

Адрес: `http://localhost:8000/orders/<int:pk>/edit/`

На странице редактирования заказа пользователь изменяет сведения о заказе, дату доставки, позиции, количество и комментарии. Система также отображает предупреждения по производству и доступности ингредиентов. После нажатия «Сохранить» изменения применяются ко всем связанным процессам.

### Рисунок 29 - Удаление заказа

Адрес: `http://localhost:8000/orders/<int:pk>/delete/`

Страница подтверждения удаления показывает выбранный заказ и предупреждает, что действие нельзя отменить. Пользователь может подтвердить удаление кнопкой «Удалить» или отменить операцию. Раздел предотвращает случайное удаление заказа.

### Рисунок 30 - Проверка доставок менеджером

Адрес: `http://localhost:8000/logistics/manager/proofs/`

На странице отображаются документы доставки, ожидающие проверки. Менеджер может отфильтровать записи по статусу проверки, открыть документ, подтвердить или отклонить его. Раздел используется для контроля фактического выполнения доставок.

### Рисунок 31 - Обновление проверки доставки

Адрес: `http://localhost:8000/logistics/manager/proofs/<int:pk>/`

Страница используется для обработки конкретного документа доставки. Менеджер проверяет файл, принимает решение и фиксирует результат проверки. После подтверждения или отклонения статус документа обновляется в системе.

### Рисунок 32 - Список отчетов

Адрес: `http://localhost:8000/reports/`

На странице отображаются отчеты с названием, периодом, статусом, результатом проверки и файлом. Менеджер может создать отчет, импортировать данные, скачать файл, запустить проверку или изменить отчет. Если отчетов нет, система показывает пустой список.

### Рисунок 33 - Аналитика менеджера

Адрес: `http://localhost:8000/reports/analytics/`

Страница аналитики содержит фильтры по периоду, статусам и клиентам. После нажатия кнопки «Показать» система отображает показатели: количество заказов, выручку, средний чек, активных клиентов, доставки и успешность доставок. Пользователь может сформировать отчет, а также скачать графики и таблицы.

### Рисунок 34 - Экспорт аналитики

Адрес: `http://localhost:8000/reports/analytics/export/`

Данный адрес используется для выгрузки аналитических данных. После выбора параметров в разделе аналитики пользователь формирует экспорт, и система подготавливает файл с показателями за выбранный период. Экспорт применяется для дальнейшего анализа или включения данных в отчетность.

### Рисунок 35 - Создание отчета

Адрес: `http://localhost:8000/reports/create/`

Страница содержит форму создания отчета. Пользователь указывает название, период и другие параметры, после чего нажимает «Сохранить». Созданный отчет появляется в общем списке и может быть проверен или скачан.

### Рисунок 36 - Редактирование отчета

Адрес: `http://localhost:8000/reports/<int:pk>/edit/`

На странице редактирования пользователь изменяет параметры существующего отчета. После сохранения система обновляет запись в списке отчетов. При необходимости пользователь может отменить действие и вернуться к списку.

### Рисунок 37 - Проверка отчета

Адрес: `http://localhost:8000/reports/<int:pk>/validate/`

Раздел используется для запуска проверки выбранного отчета. Система анализирует данные отчета и обновляет результат проверки. После выполнения пользователь видит актуальный статус в списке отчетов.

## Страницы роли логиста

### Рисунок 38 - Панель логиста

Адрес: `http://localhost:8000/dashboard/logistic/`

На панели логиста отображается обзор логистики: количество курьеров, активные грузы, доставки, маршруты и последние заказы на доставку. Страница содержит быстрые переходы к доставкам, курьерам и маршрутам. При наличии данных логист может просматривать маршруты и открывать их во внешних картах.

### Рисунок 39 - Портал логиста

Адрес: `http://localhost:8000/logistic/`

На странице портала логиста отображается список доставок с данными по заказу, курьеру, времени отправления, времени доставки и адресу. Логист может перейти к изменению параметров доставки. Раздел используется для оперативного контроля доставки заказов.

### Рисунок 40 - Планирование доставки в портале

Адрес: `http://localhost:8000/logistic/delivery/<int:pk>/`

Страница содержит форму планирования доставки для выбранного заказа. Логист назначает параметры доставки и сохраняет изменения. После сохранения информация становится доступной в логистических разделах и используется при формировании маршрутов.

### Рисунок 41 - Список доставок

Адрес: `http://localhost:8000/logistics/`

На странице отображаются заказы, требующие доставки. Логист видит клиента, адрес, плановую дату, назначенного курьера, маршрут и статус. Доступны фильтры по клиентам, курьерам, маршрутам и статусам, а также экспорт данных. Для заказов без доставки предусмотрена возможность создать доставку.

### Рисунок 42 - Карточка доставки

Адрес: `http://localhost:8000/logistics/delivery/<int:pk>/`

Карточка доставки содержит данные заказа, клиента, адрес, сумму и параметры груза. Система показывает подходящих курьеров и форму планирования доставки. Также отображается карта маршрута или ссылка для открытия адреса в Google Maps.

### Рисунок 43 - Редактирование доставки

Адрес: `http://localhost:8000/logistics/delivery/<int:pk>/edit/`

На странице редактирования доставки логист изменяет параметры выбранной доставки. После заполнения формы пользователь нажимает кнопку «Сохранить». Измененные данные используются при планировании маршрутов и назначении курьеров.

### Рисунок 44 - Создание доставки по заказу

Адрес: `http://localhost:8000/logistics/orders/<int:order_id>/delivery/`

Страница используется для создания доставки на основании выбранного заказа. Система подставляет данные заказа и клиента, после чего логист указывает параметры доставки. После сохранения доставка появляется в списке логистики.

Адрес: `http://localhost:8000/api/token/`

Данный адрес используется для получения JWT-токена по учетным данным пользователя. Клиентская или внешняя система передает логин и пароль, после чего сервер возвращает токен доступа и токен обновления. Полученный токен применяется для авторизованных API-запросов.

### Рисунок 95 - Обновление токена доступа

Адрес: `http://localhost:8000/api/token/refresh/`

Раздел предназначен для обновления токена доступа без повторного ввода логина и пароля. Внешняя система отправляет refresh-токен, а сервер возвращает новый access-токен. Механизм позволяет поддерживать авторизованную работу API-клиента.

### Рисунок 96 - Проверка доступности заказа

Эта функция помогает заранее определить, можно ли принять заказ в работу без нарушения производственных лимитов.
